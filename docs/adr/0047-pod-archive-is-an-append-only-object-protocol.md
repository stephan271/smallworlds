# Pod archive is an append-only object protocol, not a Solid server

Personal data pods will be implemented as a minimal append-only object protocol served by a `pod-gateway` tenant in front of Garage, rather than by Community Solid Server as the design exploration first proposed. CSS is itself an identity provider speaking Solid-OIDC, so adopting it would introduce a second login separate from Keycloak and break the project-wide rule that tenants are plain OIDC relying parties reading `keycloak-secret`; the exploration also rates CSS experimental and low-velocity. The gateway keeps Solid's semantics — a per-user container, a service agent holding `Append` and nothing else, per-user isolation — while defining its own wire format: `PUT` creates an object and returns `409` if the key already exists, agents have no `GET` or `DELETE` verb at all, and every append extends a hash-chained per-user manifest so a home device can verify that no entry was removed, reordered, or rewritten. Append-only cannot be delegated to Garage, whose keys are per-bucket `read`/`write`/`owner` with no prefix scoping and whose `write` permission includes `DeleteObject`, which is why an enforcement point in front of it is required rather than merely convenient. Immich is the first source app and its exporter reads a per-user inventory from the CNPG database through a read-only role and the bytes from `immich-library-pvc` mounted read-only, accepting coupling to Immich's schema in exchange for needing no per-user API keys and no admin impersonation; the exporter fails loudly on schema drift. The pod archive is the sole server-side copy of append-only source data: the `pv-backup` mirror of the Immich library is removed rather than kept alongside it, and the `pods` bucket is not replicated offsite, leaving pixels in two failure domains — the node disk and user home devices — which is a deliberate acceptance of disaster risk in exchange for eliminating duplicate copies of the same bytes on the same disk. Central database backups are unaffected, because album membership, face names, and tags are user intent that is irreplaceable and has no pod home.
