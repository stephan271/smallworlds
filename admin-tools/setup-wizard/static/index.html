Your community

Two answers. Everything else has a sensible default you can change later in your settings repository.

Every application is named under this — files.example.org, photos.example.org, and so on. You register it with a registrar yourself; nothing here buys a domain.

Used for the Let's Encrypt account and as the operator contact. It is not published to members.

Advanced settings

Leave empty for production. Set .dev to run a second cluster beside it at files.dev.example.org.

Where it runs

One machine runs everything. You can move it later; the settings repository is what carries your cluster, not the hardware.

Needs read and write. Used to create the server and to manage DNS records. It never leaves this machine except to Hetzner.

Needs a systemd Linux, SSH key access and sudo rights.

Storage and certificates

Must be on a second physical disk. Backups have to survive losing the operational disk, so the installer refuses a single device.

Let's Encrypt proves the domain with a DNS record, so it needs no port forwarding and no public IP — a LAN-only cluster gets publicly trusted certificates too.

Needs a public IPv4 without CGNAT and these forwards on your router: 80/tcp, 443/tcp, 10000/udp.

Both Let's Encrypt and internet exposure write records into Hetzner DNS. Not needed if you chose self-signed and LAN only.

Your settings repository

A private Git repository holds your cluster's configuration. This is the durable part: the cluster follows it, and it is what you would restore from. The wizard writes it once and then gets out of the way.

Needs repository read/write, and pull-request rights so the weekly update proposals can be opened. Argo CD reads your repository with this token.

Advanced settings

Pinning keeps updates deliberate: the cluster only adopts a newer release when you bump this and commit.

What your community gets

Start with what you will actually use. Applications can be added later; removing one is harder, so leaving a box unticked costs you nothing.
